## 1. 🔴 즉시 (운영에 직접 리스크)

### 1-1. 월간 정산 크론 N+1 — 데이터 늘면 타임아웃 위험 ✅직접확인
`src/app/api/cron/monthly/route.ts:43~80` — 최대 5,000개 계약을 **루프 돌며 계약당 쿼리 2번(청구·스케줄) + upsert 1번**. 최악 ~15,000회 순차 호출 → Vercel 함수 타임아웃 가능. 계약/청구가 늘수록 매월 1일 정산이 멈출 수 있음.
→ **집계 쿼리(GROUP BY lease_id) 1~2방으로 재작성.** (효율 M)

### 1-2. 알림(카톡·SMS·이메일) 전부 모의(mock) — 가장 큰 공백 ✅직접확인
`src/lib/notify/adapters/kakao.ts`,`sms.ts` 전부 `*_stub_not_implemented` 반환. 만료 알림·임대인 월간보고·연체 안내·부동산 승인 문자 → **콘솔+DB 기록만, 실제 발송 0건**. (DB `notifications` 기록은 정상이라 키만 넣으면 전환됨)
→ 카카오 비즈메시지 또는 NCP SENS 키 확보 후 어댑터 구현. (외부절차 + 개발 L)

### 1-3. 경매 답사 — 정확성 함정 3건 (오늘 number 전환으로 일부만 해결)
오늘 번호충돌은 막았지만 아래는 남음:
- **A. fill_rest의 sheet_id 덮어쓰기** ✅: `survey-pdf/route.tsx:66`이 발급마다 `sheet_id`를 무조건 덮어씀 → 같은 물건을 전체+지역 두 번 뽑으면 먼저 종이(A)의 "나머지 거주" 집합에서 빠지고, UI 미리보기 건수(`total_count` 기준)도 어긋남. (효율 S)
- **B. 중복 발송 무방비** ✅: pending 물건이 전체·지역 두 종이에 동시 등장 → 두 팀이 같은 집. `route.tsx`에 `sheet_id IS NULL` 가드 없음. (효율 S)
- **D. 전역 매칭 오타 무경고** ✅: 일반 일괄입력은 `survey-actions.ts`에서 `property_no` 전역 매칭이라, 오타 번호도 실재하면 **엉뚱한 물건을 조용히 공실/거주 처리**. (효율 S — 발급 선택 시 그 발급 소속인지 검증 추가 권장)

> 사용자 결정: 6자리 번호 오타 자체는 걱정 안 함. 그래도 D의 "무경고 오작동"은 발급검증/미리보기로 싸게 보완 가능.

### 1-4. 운영 환경변수 — 게이트 확인 ✅부분확인
- `CRON_SECRET`: daily/monthly는 **미설정 시 401(안전)**, 그러나 `lease-expiry`·`landlord-monthly-report`는 **미설정 시 인증 건너뛰고 실행(fail-open)** (`route.ts:65`,`:23`). → 4개 모두 fail-closed로 통일 + Vercel에 키 설정 확인.
- `PII_ENCRYPTION_KEY`: 없으면 계좌·주민번호가 평문 저장 폴백(`crypto-pii.ts`). **운영 키 설정 반드시 확인.**

## 2. 🟡 단기 (업무 효율·안정)

### 관리자 OS
- **대형 리스트에 검색·페이지네이션 없음**: rent·complaints·inquiries·leases·tenants·properties가 200~500건 상한, 그 이상은 안 보임. 조직 커지면 막힘. → 서버 검색 파라미터 + 커서 페이지네이션. (L)
- **일괄 내보내기(CSV/엑셀) 부재**: owners만 엑셀 있음. rent·complaints·inquiries엔 없음. (M)
- **파괴적 동작이 브라우저 `confirm()`**: 물건/부동산/인증서 삭제, 멤버 반려가 `confirm()`·`window.prompt()` 사용 → 공용 `ConfirmDialog`(멤버 화면에 이미 있음)로 통일. (M)
- **은행입금 매칭(`/admin/rent/match`)이 메인에 안 노출** → rent 화면 상단 버튼화. (S)
- **계약 갱신 빠른 버튼 없음**: 갱신 시 10+필드 재입력 → 활성 계약 카드에 "갱신"(90% 자동채움). (M)

### 경매 모듈 (정확성·성능 잔여)
- **C. 재수집 중복행** ✅: 수집 중복차단이 `address + pending`만 봄(`collection/actions.ts:96~100`) → 이미 답사끝난(non-pending) 주소를 2차 전수조사 때 재수집하면 **새 property_no로 중복행** 생성. → `.eq("survey_status","pending")`를 `.neq(...,"rejected")`로. (S)
- **getOpenSheets N+1**: `survey-actions.ts:177~188`이 발급별 건수를 루프로 30+회 조회 → GROUP BY 1방. (M)
- **dedup 인덱스**: `(address, survey_status)` 복합 인덱스 없음 → 30k에서 수집 느려짐. (S)
- **파서 견고성**: `lib/auction/court-auction.ts` 모바일 줄바꿈 정규화가 특정 패턴만 처리 → 비정형 붙여넣기 시 블록 병합 위험. 악성입력 테스트 코퍼스 추가. (M)
- **case_number 유니크 제약 없음** → 같은 사건 2회 수집 시 중복. (S, ON CONFLICT 처리)

## 3. 🟢 다듬기 (디자인·품질)

### 디자인 가이드(흰배경·네이비 단색·그라데이션/다크 금지) 위반
- **푸터가 `bg-slate-900`(회색)** — 네이비(`bg-primary`)로. (`components/layout/Footer.tsx:44`) (M)
- **보조 강조색 남용**(emerald/rose/sky/amber 등 50+곳) — 상태색만 남기고 네이비 단색 회귀. (M)
- **블로그 그라데이션 배경**(radial/HSL) — 가이드 위반. (`(public)/blog/page.tsx`,`[slug]`) (M)
- 일부 다크 섹션 backdrop-blur·반투명 오버레이. (S)

### 콘텐츠·SEO
- **OG 기본 이미지 확인 필요**: 메타가 `/og-default.png` 참조하나 `public/`에 없음(동적 `api/og`는 존재) → 메타를 `api/og`로 통일하거나 파일 추가. (M)
- **Unsplash 임시 사진**: `lib/data/site-images.ts` 전부 Unsplash → 실제 매물/대표 사진 교체. (L, 박성혁 사진 액션)
- 일부 `<img>` 원시 태그(최적화 미적용) → `next/image`. (M)
- (정정) sitemap·robots·JSON-LD 구조화데이터는 **이미 잘 구현됨**. 손댈 것 없음.

### 코드 일관성
- **상태 라벨 상수 5+곳 중복 정의**(rent/complaints/leases/members…) → `@/lib/labels.ts`로 통합. (M)
- **빈 상태(empty state) 문구·디자인 제각각** → `EmptyState` 공용 컴포넌트. (S)
- 랜딩 하드코딩 hex(`bg-[#E8EBF0]` 등) → 토큰화. (S)

## 4. 💡 편의성 아이디어 (효과 큰 순)

1. **답사지 번호 QR + 휴대폰 스캔 입력** — PDF 각 줄에 `property_no` QR → 현장팀이 폰으로 스캔하면 일괄입력 자동 채움. 6자리 수기/타이핑 오타 사실상 0. (경매 워크플로 최대 개선, M)
2. **명령 팔레트(Cmd/Ctrl+K)** — "임차인 추가/입금 기록/계약 갱신" 빠른 실행. (M)
3. **저장 필터 + 대시보드 KPI 클릭→필터링 이동** — "이번달 연체" 등 반복 조건 저장, KPI 카드가 해당 목록으로 링크. (S~M)
4. **일괄입력 Undo(5분)** — 잘못된 발급에 fill_rest 실행 시 되돌리기. (S)
5. **판정→재수집 마법사** — "전수조사필수" 임대인의 물건 목록을 수집 폼으로 1클릭 전달. (M)
6. **발급 전 지역 충돌 경고** — 여러 지역 섞어 선택 시 "이 지역만 인쇄됩니다" 확인. (M)
